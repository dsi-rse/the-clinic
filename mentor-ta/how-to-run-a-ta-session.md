## How to run a TA Session

This document contains a short checklist that can be used to assist in organizing the TA session.

- [ ] Take attendance.
- [ ] Verify the expected tasks for each student with each student so that they know what they are expected to do. Their tasks are the GitHub issues they opened after the mentor session.
- [ ] Confirm that every student has code pushed, or a clear plan to push before the deadline. **A student with no pushed code by midnight before the mentor session receives a 0 for the week** — this session is where you catch that.
- [ ] Review any open pull requests with the `/clinic-pr-review` skill, then leave your review on the pull request. Check that students have responded to your previous review comments.
- [ ] Work through technical blockers. This is the place for debugging — mentors are instructed not to debug code during the mentor meeting.
- [ ] Escalate any technical issue you cannot resolve to clinic staff, and any other student concern to the mentor or clinic administration. See [escalation](./escalation.md).
- [ ] Take a look at the [class schedule](../syllabus/weekly-plan.md) and Canvas in order to make sure that any upcoming deadlines are noted.
- [ ] At the conclusion go to Canvas and insert the students' attendance grades.
- [ ] Post your weekly update for this project to the thread in the clinic TAs Slack channel.
