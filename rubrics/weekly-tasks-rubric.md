# Weekly Tasks Grading Rubric

Weekly tasks outline each team member's assigned work for the next week. They are opened as GitHub issues in the project repository, following the [weekly tasks template](../templates/weekly-tasks.md).

## Requirements
Each student opens a GitHub issue (or issues) describing their tasks for the coming week, with clear acceptance criteria for each task, and posts a link to the issue(s) in the weekly Slack thread for the project.

## Logistics and Timing
The deadlines are based on the day of the mentor session. Weekly tasks are due at midnight on the day of the mentor session.

## Grading
Grades are assigned on a scale of 0-5 points and each student in the group may receive a different grade. Grades are recorded individually for each student in Canvas; filtering the gradebook by project group makes this easier.

Tasks should be assigned to a single individual. If the same task is repeated for multiple people, it should be broken up into smaller individual tasks, each assigned to a single person.

Mentors may apply additional grading standards to the rubric below.

Two points of emphasis:
   1. Don't fall behind on grading!
   2. Make sure to establish standards early. Giving everyone a 5 for everything is going to encourage people to slack; make sure that the high performers are rewarded and people who are slacking know that you are aware of their lack-of-effort.

| Grade | Description |
| ----------- | ----------- |
| 5 | Issue opened on time and linked in the Slack thread. Every task has clear, checkable acceptance criteria and is descriptive, complete, and easy to follow. No grammar, formatting or style errors present in the writing. |
| 4 | Issue opened and linked, but there are minor grammar, formatting or style errors OR the task description or acceptance criteria aren't sufficiently complete. |
| 3 | Issue opened and linked, but with significant presentation (style/grammar/formatting) or description problems, or acceptance criteria that are too vague to check. Demonstrates a lack of effort. |
| 2 | Missing information (for example, no acceptance criteria or no Slack link), significant presentation and content issues. |
| 1 | Incomplete and demonstrates a lack of effort. |
| 0 | Zero effort / no issue opened |


## Late Policy

Late submissions made within 24 hours of the deadline will automatically be docked two points. Submissions after that time will receive a grade of zero. The issue creation time and Slack post time are used to determine whether a submission is late.
